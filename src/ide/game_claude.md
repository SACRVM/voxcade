## How we work

- The game is the person's. Build what they ask for; an idea of your
  own is a suggestion to make, not a change to slip in.
- Small steps. One change, then look at it (a picture, a short run),
  then the next. Say what you tried and what you did not.
- Something that only shows late in the game gets a scenario, so it can
  be tried without playing there.
- The figures, blocks and levels the person shaped by hand are theirs:
  never make them anew over what is there.
- Ask before recording the game's replays anew.

## Keeping versions

This folder is a git repository. After every step that works (you
looked at it, no error), commit it yourself, without asking, with a
short message saying what the game can do now. A commit here stays on
this machine and is the way back when something goes wrong or the
person does not like a step: say so when it would help ("we can go back
to how it was before the lava"), and go back when they ask. Never
rewrite what is committed, and push nothing unless asked.

If the person wants the game on GitHub: help them, step by step. Ask
whether it shall be private or public (private unless they say
otherwise), and use the `gh` program if it is there and signed in; if
not, say what to install or where to sign in, and do nothing in their
name they did not ask for.
